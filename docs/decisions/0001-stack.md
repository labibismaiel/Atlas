# 0001 · Stack: Vue 3, TypeScript, Vite, Sass, Vitest

## Context

The brief names the team's own stack (Vue, TypeScript, Sass) and allows any testing suite. The
app is a client-side SPA with two routes that reads a public, read-only API.

## Decision

- **Vue 3** with `<script setup>` and the Composition API, scaffolded with `create-vue`.
- **TypeScript** in strict mode with `noUncheckedIndexedAccess`.
- **Vite** for the dev server and build, **Vue Router** for the two views.
- **Sass** (`sass-embedded`) for authoring, with CSS custom properties for the design tokens
  ([0008](0008-styling.md)).
- **Vitest + Vue Test Utils + jsdom** for unit and component tests ([0010](0010-testing.md)).
- **ESLint + Oxlint + Prettier**, as generated by `create-vue`.
- **Fonts self-hosted through Fontsource** (Michroma for display text, Source Sans 3 for body
  text). This means no request to a third-party font CDN, no consent issue, and they work offline
  in development.

## Consequences

- No **Nuxt**: there is no SEO or SSR requirement, and a static SPA deploys to Vercel as plain
  files.
- No **Axios**: `fetch` with `AbortController` covers everything needed. A ~60-line wrapper adds
  error normalisation and a timeout ([0006](0006-error-handling.md)).
- No **Pinia**, **TanStack Query** or **VueUse**. Each was considered and rejected as more than
  this problem needs ([0003](0003-state-and-url.md), [0004](0004-search-request-lifecycle.md)).
  The runtime dependencies are only `vue`, `vue-router` and the two font packages.
- The scaffold's toolchain is very recent (Vite 8, TypeScript 6, Vue Router 5). The project only
  uses Vue Router's classic, stable API (`createRouter`, `RouterLink`), not its newer
  file-based routing.
